01 / BASELINE MATCHING BIAS

Accidental parity with trivial Always-Escalate

In the Golden Set, 180 of 250 queries (72.0%) are Gold ESCALATE. A brainless "Always-Escalate" dummy model that forwards 100% of tickets to human agents achieves exactly 72.00% binary accuracy without reading a single word. Our 72% headline reflects safe conservatism, not intelligent deflection.

EMPIRICAL ERROR ANALYSIS / 5 MODES

Failure Lab: Exactly Five Verified Failure Modes

Systematic failure taxonomy derived from the frozen 250-example Golden Set evaluation (reports/failure_analysis.md).

MODE 01 / CRITICAL SAFETY & SECURITY

Under-Escalation on High-Risk / Complex Inquiries

8 / 180 Gold ESCALATE cases under-escalated (4.44% error rate)
Concise Impact: False self-service guidance promises automated resolution for issues where online tools have already failed, 2FA credentials require alteration, or persistent hardware crash loops require warranty service.
Representative Real Golden Cases:
golden_candidate_0035

"order may be ineligible for changes online and chat is unavailable" → Predicted orders_delivery (conf 0.909), auto-handled with generic link when chat was offline.

golden_candidate_0132

"Your two factor authentication is awful... turning it off is impossible!" → Predicted apple_id_account (conf 0.636), auto-handled instead of enforcing account security boundary.

golden_candidate_0062

"phone is still restarting every 30 seconds" → Predicted software_update (conf 0.863), auto-handled despite persistent crash loop.

MEASURED FACT: Exactly 8 Gold ESCALATE were auto-handled. Zero critical safety keywords fired on these cases.
HYPOTHESIS: Threshold gating permits AUTO_HANDLE when confidence ≥ 0.50 and similarity ≥ 0.35, blind to user statements of tool failure.
FUTURE WORK
One-Week Mitigation: Negative-intent regex guards for prior failure ("already tried", "ineligible.*online", "chat.*unavailable"); mandatory human routing on 2FA disabling; customer confirmation before auto-resolving hardware reboots.
MODE 02 / AUTOMATION STARVATION

Excessive Withholding & False Escalation of Automatable Queries

62 / 70 Gold AUTO withheld (88.57% false escalation rate)
Concise Impact: Severe self-service starvation; the agent resolves only 8 of 70 valid automatable cases, diverting 38 to clarification and 24 to human escalation. Total deflection is depressed to 6.4%.
Representative Real Golden Cases:
golden_candidate_0006

"How to change my personal name associated with my apple ID?" → Confidence 0.968, similarity 0.384; escalated solely because evidence lacked an extracted link.

golden_candidate_0015

"whether intermittent charging is better for battery than full charge" → Confidence 0.795; escalated because lexical similarity was 0.271 (< 0.35 cutoff).

golden_candidate_0026

"says searching and occasionally no service" → Standard cellular self-service troubleshooting escalated due to similarity 0.330 (< 0.35).

MEASURED FACT: 62 of 70 automatable queries were withheld; 100% of these 62 lacked either a verified URL or ≥ 0.35 cosine similarity.
HYPOTHESIS: Rigid conjunction of requiring an extracted URL + 0.35 lexical cutoff suppresses valid, high-confidence guidance.
FUTURE WORK
One-Week Mitigation: Allow text-only grounded replies when confidence ≥ 0.80 and similarity ≥ 0.30 without requiring an external link; lower similarity threshold to 0.30 for informational intents (battery_power, how_to_information).
MODE 03 / CUSTOMER FRICTION

Monolithic Clarification Loop & Premature Triage Trap

126 / 142 generated replies (88.73%) used static canned templates
Concise Impact: High customer dialogue friction; 88.7% of all generated responses are identical unparameterized mobile triage prompts asking for device model and iOS version already stated by the user.
Representative Real Golden Cases:
golden_candidate_0191

"Will not take CC credentials on an iPhone 6s" → Agent blindly asks for device model already explicitly stated.

golden_candidate_0001

"When trying to install free apps on an iPhone 6s..." → Agent asks for device model already provided in opening sentence.

golden_candidate_0025

"bought my old work computer... was wiped... password hint doesn't work" → Customer asks about Mac; agent asks for iOS version.

MEASURED FACT: 126 clarification replies used identical templates. In queries naming "iPhone 6s", the template asked for device model.
HYPOTHESIS: Offline generator lacks slot/entity extraction before rendering the clarification template.
FUTURE WORK
One-Week Mitigation: Regex slot extractors for hardware (iPhone 6s, Mac) and OS (iOS 11, High Sierra); branch templates by platform; omit questions for slots already present in customer message.
MODE 04 / GROUNDING FIDELITY

Link Validity Degradation & Ephemeral Twitter DM Shortlinks

16 / 16 AUTO replies (100.0%) cite t.co links; 7 cite DM invite; 0 cite Apple KB
Concise Impact: Repurposing historical tweet shortlinks promises "find the steps to resolve this here" while actually pointing to ephemeral Twitter DM invitation links rather than canonical Apple support documentation.
Representative Real Golden Cases:
golden_candidate_0066

"trying to run update from App Store" → Auto-handled citing https://t.co/GDrqU22YpT (a Twitter DM invite link).

golden_candidate_0039

"on my iPhone 'is' keeps autocorrecting to I.S" → Autocorrect bug paired with historical DM invitation shortlink.

golden_candidate_0193

"The battery drain is real @115858 #ios11" → Auto-handled citing raw t.co link from historical tweet.

MEASURED FACT: 100% of AUTO replies cite t.co shortlinks; 43.75% cite DM links; 0% cite support.apple.com.
HYPOTHESIS: TF-IDF retrieval matches brand tokens rather than resolution text; URL guard checks verbatim presence in evidence without domain whitelisting.
FUTURE WORK
One-Week Mitigation: Enforce strict domain whitelisting (permitting only support.apple.com, appleid.apple.com); reject or strip t.co DM links; index curated official Knowledge Base articles.
MODE 05 / CONTEXT BOUNDARY DEFICIT

Conversational Anaphora & Context Boundary Deficit

250 / 250 in threads >1 turn; 96 have prior context; 29 anaphoric errors resolvable
Concise Impact: Inbound turns evaluated in isolation cannot resolve pronouns (*"it"*, *"this"*, *"still"*) referring to antecedent turns, causing classifier uncertainty and unnecessary abstention to other_unclear.
Representative Real Golden Cases:
golden_candidate_0017

"it asks for a user and a passwort... why did it appear all of a sudden?" → Turn 1 established unauthorized new user login screen after Mac update.

golden_candidate_0034

"Took maybe an hour to recover all photos... stop it happening" → Turn 1 established customer was discussing iCloud photo recovery.

golden_candidate_0059

"Updated apps reset device still very glitchy" → Prior turns showed ongoing complaints about persistent UI freezing.

MEASURED FACT: 250/250 threads >1 turn; 96 have prior context; 66/122 intent errors contain anaphoric markers; 29 of those had prior thread context available.
HYPOTHESIS: Single-turn inference caused pronoun misclassification. Causal accuracy lift from conversation history is an unmeasured hypothesis until experimentally tested.
FUTURE WORK
One-Week Mitigation: Add conversation_history parameter to AgentController; prepend prior turns with turn boundary tokens; experimentally benchmark causal accuracy lift on the 96 multi-turn Golden examples.
